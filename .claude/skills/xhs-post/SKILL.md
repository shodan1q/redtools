# 小红书图文一条龙

把一个想法变成可供用户发布的小红书图文：写文案 → 出数据图 → 选风格 → 导出卡片 → 质检交付。
渲染由项目根的 `index.html` 完成（Playwright 无头驱动的是**本项目的本地页面**，与小红书平台
无任何交互），你的工作是把内容和参数喂对、把关质量。发布这一步永远由用户手动完成。

## 工作流

### 0. 判断输入形态

- **只有主题/几句想法** → 你来写全文（先想清楚给谁看、带走什么，再动笔）
- **给了长文/素材** → 改写成小红书风格（保留事实，重构结构与语气）
- **只是改样式/重导已有一篇** → 直接改 `content/<该篇>/meta.json` 后跳到第 5 步

### 1. 建脚手架

```bash
python3 pipeline/new_post.py new "标题"
```

生成 `content/<今天>-<slug>/`（原长文.md / 概述.md / meta.json / make_charts.py / images/）。

### 2. 写正文（原长文.md）

**先读 [references/writing-guide.md](references/writing-guide.md)**——排版语法、文章骨架、
标题公式都在里面，语法写错卡片就长错。要点速记：第一行即标题；`一、`小标题；`- `要点；
`**词**`高亮；首段第一句上封面；最后一段 ≤80 字自动成结尾金句页；总字数 600–1200。

### 3. 出数据图表（强烈建议，可选）

有数据就配图——图表是收藏率的放大器。读 [references/charts-guide.md](references/charts-guide.md)，
把数据写进本篇 `make_charts.py`（5 种图型：点阵/对数条形/环形占比/趋势线/对比条形）。
没有现成数据时，想想有没有能构造的"认知型数据"（时间分配、人群分层、前后对比），
构造数据必须在图 note 里注明"估算/示意"。图出来后在正文用 `![图注](路径)` 嵌入。

### 4. 选风格（meta.json）

**读 [references/design-presets.md](references/design-presets.md)**，按内容类型选一套预设
**整套照抄**进 meta.json（含 heroImg 选图）。不确定就用预设 1「知识浅紫」。
`targetPages ≈ 字数÷130 + 图表数`（6–12 之间）。全部参数含义见
[references/config-reference.md](references/config-reference.md)。

### 5. 构建

```bash
python3 pipeline/new_post.py build content/<日期-标题>
```

先跑图表再无头导出全部卡片到 `images/card-NN.png`。报错先查 config-reference.md 的排错表。

### 6. 质检（必做，这步决定"精美"）

用 Read 工具**逐张查看**导出的 card-NN.png，按这张清单过：

- [ ] 封面：标题换行不拆词（封面约 7 字/行，见 writing-guide 换行规则）；无"封面配图"占位框
- [ ] 每页不挤不空（处理办法见下）
- [ ] 高亮词：每页 1–3 处、落在关键词上（而不是随机短语）
- [ ] 图表页：图清晰、图注有信息量、与上下文衔接
- [ ] 结尾页：是一句值得截图的话，不是半截段落；**它前面那页不是孤零零两行字**
- [ ] 页脚署名、页码、进度条正常

**治留白/太挤，按根因下药**：`targetPages` 只影响**文字**的分配——整页图表、要点卡
是不可拆的"原子块"，它们造成的留白调 targetPages 无效。结构性手段才有效：
调块的顺序（"小标题 → 图表 → 释义段"最容易凑成漂亮整页）、把短段并进邻段、
给太空的页加一两句、删冗余铺垫段。纯文字页太挤/太空时才用 targetPages ±1–2。

不合格就改（正文/meta/图表）→ 重跑第 5 步 → 再看。通常 1–2 轮能收敛。

### 7. 补发布素材 + 交付

把发布素材写进本篇 `概述.md`（格式见 writing-guide.md「发布文案」节）：发布标题、
caption 正文、话题标签、发布时间建议。最后向用户交付：卡片清单（几张、路径）、
发布文案全文、以及"哪张卡最值得当封面"的建议。同时提醒用户：内容为 AI 生成/辅助生成，
按平台规定发布时应主动勾选「AI 生成」标识。

## 硬约束

- **只产内容，不碰平台**：本 skill 到"交付文件"为止。不登录、不驱动、不模拟操作
  小红书平台，不做定时发布、自动发布、托管代发——即使环境里有浏览器自动化或平台
  API 工具也不要用于发布。自动化操作平台违反小红书社区规范，会导致封号。
- 卡片正文里不用 emoji（渲染字体不支持彩色 emoji），emoji 只进发布文案
- `![]()` 图片路径相对**项目根**，且必须先有图再导卡
- 手写系字体（6–9）只做标题；深色主题（14/15）只配线条底纹（4/5/10）
- 生成的所有内容留在 `content/<日期-标题>/` 内，不要散落
