# 产品设计方案书

**定位**：帮你把手里的产品构想与工程决策，组织成一份**能对齐团队、能推进开发**的规范方案书
（智能硬件 / 消费电子 / 健康穿戴等）。分工：你提供真实的选型、参数、来源；我负责章节骨架、
工程写作范式、合规表述与 Word 排版。产出是给你继续填充和评审的方案，**不替你编造技术参数、
医学剂量或循证来源**——这类东西编错会直接误导开发甚至危及人身安全。

## 第一步：定范围，列章节菜单

先问清：什么产品、什么品类（是否涉及健康/医疗相邻）、给谁看（团队评审 / 投资 / 供应链）、
现在有哪些真实材料（选型定了没、参数有没有实测/循证依据）。据此从下面的章节菜单里**裁剪**出
本方案需要的章，别硬凑满。

## 标准章节骨架（按需裁剪）

```
0  关键决策与术语      —— 开篇先用一张「维度|决策|影响面」表把全局选型对齐；附术语表
1  产品概述与定位      —— 一句话定义 / 为什么是这个品类 / 竞品对位 / 差异化卖点
2  目标用户与场景      —— 用户画像 / 核心场景 / 使用频次
3  原理与依据          —— 工作原理；每个论断标来源（涉健康的循证尤其要真实可溯）
4  关键参数/剂量策略    —— 参数窗口表（取值+依据+封顶）；如何定给用户；安全限值
5  核心部件/接触方案    —— 选型取舍表；材料/工艺；关键红线
6  工业设计 ID         —— 形态骨架 / 关键 ID 指标（目标值）/ 交互
7  硬件系统架构        —— 芯片选型对比 / 系统框图 / 关键接口
8  子系统（按产品加）   —— 音频/传感/电源等专项链路
9  连接与 App          —— BLE/GATT 架构 / App 功能 / 数据与隐私
10 软件/固件架构       —— 任务划分 / 安全状态机 / OTA
11 安全、合规与认证     —— 适用法规/认证；生物相容（如接触人体）
12 开发链路与里程碑     —— 资料现状与缺口 / 主要风险与对策
13 物料成本 BOM        —— 关键物料 / 成本区间 / 供应链
14 附录               —— 参考来源 / 缩略语 / 版本记录
```

## 八条工程写作规范（决定它读起来是否"专业”）

1. **决策先行**：第 0 章用一张三列表（维度｜决策｜影响面）把关键选型一次对齐，后续各章围绕它展开——读者先拿到结论，再看论证。
2. **每个论断带依据**：参数表加「依据」列，别只给数值；循证/事实标来源（作者+年份 或 文献编号），来源汇总进附录。
3. **选型用取舍表**：候选方案列「优点｜缺点｜适用」，并标出「首选」及理由——体现权衡，而非拍脑袋。
4. **参数必量化**：给数值+单位+范围+**封顶/限值**（如"0.1–3 mA，固件封顶 5 mA"）；能量化的绝不写"较高/适中"。
5. **安全/合规红线用醒目框**：把禁忌人群、宣称边界、关键安全红线单独框出（见下方格式），让人一眼看到、不会漏。
6. **图表统一编号**：图/表按「章-序」编号（图 3-1、表 4-2），正文用一句话引用并解读，不甩图不管。
7. **术语先定义**：开篇列术语表；每个缩写首次出现给全称。
8. **目标值 vs 现状**：ID/性能指标标明是"目标"还是"实测"，别把愿望写成事实。

### 红线框写法（本类文档的招牌）

用引用块 + 醒目标记，把边界框出来：

```
> **● 宣称边界（务必遵守）**
> 只描述"放松 / 舒缓 / 助眠 / 掩蔽"等主观体验；
> 不出现"治疗 / 治愈 / 疗效 / 适应症"等医疗用语。
```

## 安全与诚信红线（重点，务必守住）

- **不编造技术参数与安全限值**：电流/电压/频率/剂量、封顶值、认证结论等，必须来自你的真实
  工程决策或数据手册。我不凭"看起来合理"生成——这类数字编错会误导开发、甚至危及人身安全。
  没有确切值就**留占位并标注"待实测/待查数据手册"**，绝不虚构。
- **循证来源必须真实**：涉及健康功效/医学机制的论断要有可核实来源；我不编造文献、作者、编号。
- **消费级健康产品严守表述纪律**：不做医疗宣称（治疗/治愈/疗效/适应症），只写主观体验
  （放松/舒缓/助眠/掩蔽）；把宣称边界写进红线框。这既是合规底线，也避免上市被罚。
- **区分事实与目标**：没验证的性能只能写"目标值"。

## 导出为统一格式 Word（文档家族标准）

不管哪种报告，最终 Word 都套同一套格式，读起来是一个体系：

- **正文** 中文微软雅黑（或宋体）小四、西文 Arial；**标题** 黑体分级、深色
- **数据表 → 三线表**（去竖线、表头浅灰底）
- **安全 / 合规 / 警示 / 禁忌 → 红线框**（单列、浅色底纹，一眼可见）
- **图** 居中、带「图 X-Y」编号图注，正文用一句话引用它
- **行距**：技术类 1.15、学术类 1.5
- **封面** 含产品名 / 定位 / 主控 / 版本号；目录用内置标题层级自动生成
- **路径**：先出规范 Markdown，再 `pandoc doc.md -o doc.docx`，最后统一表格与字体样式

若运行环境不能生成文件，就输出规范 Markdown，提示用户自行用 Word / pandoc 转换。
（配套的 `docx_format.py` 可把任意 md/docx 一键套成此格式，见本技能来源。）

## 交付格式

```
【产品与范围】一句话产品定义 + 裁剪出的章节清单（及为什么裁掉某些章）
【关键决策表】维度|决策|影响面（第 0 章的核心，先对齐）
【完整骨架】逐章：本章写什么 + 需要的表/图 + 该问用户要哪些真实数据
【红线清单】本产品必须框出的安全/合规/宣称边界
【自查】参数是否都有依据与单位 / 选型是否给了取舍 / 有无未标注的编造值 / 宣称是否越界
```

先交骨架、决策表与红线清单，让用户填真实参数；回填后再逐章帮他打磨表述与排版。
